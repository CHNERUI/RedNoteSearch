## 区域与字段

| 区域 | 当前契约 | 提案 |
|---|---|---|
| 对象类型 | `POST /tasks.product_id` 为单值 | `promotion_target.kind`：single / multiple / activity（字段名待 A 定稿） |
| 单品 / 多品 | `GET /brands/{brand_id}/products?status=active` 的 id、name | 单品 1 个；多品 2–5 个去重商品 id；限同品牌未归档商品 |
| 活动 | 无结构化活动字段 | 名称必填、说明必填、福利选填；建议分别限制 100 / 2000 / 2000 码点，均为待确认限制，不是现有接口限制 |
| 活动依据 | `task_materials` 或已有任务文件上传 | 沿用资料入口；临时资料显示“未经审核”，不把活动表单当作审核依据 |
| 摘要 | `GET /tasks` 的 product_id、product_name；版本已有 task_id | 对象类型、名称、商品数和创建时快照（待新增）；多品列表摘要截断，详情可展开全部，不用 UUID 代替名称 |
| 优惠断言 | `claim_evidence` 的 status / human_confirmed 等 | 结果页无依据时显示“需人工判断”；活动福利不得自动转为成立 |

## 交互

1. 三选一控件用 radio group，键盘方向键切换；首次默认单品，明确选择后才可创建。图中的创作类型仅是接口返回值的示例，不在代码中写死选项。
2. 切换类型在本地保留各自草稿，但提交只含当前类型；切品牌清除对象与商品选择，防止串品牌。离开未保存页面提示。
3. 多品搜索选择器显示“已选 N / 5”，达上限时对未选项禁用并说明原因；不能把 1 个商品默认为多品提交。归档、越权与并发变化由服务端重新校验；409/422 保留草稿。
4. 活动无需虚构商品。福利留空表示无已填写福利，不自动写“优惠”“限时”或补造促销内容。活动日期本次未要求，不擅自增加必填日期。
5. 创建前的橙色提示只是资料缺失预提示，不表示执行过证据检查；准确状态以生成后的检查结果为准。草图“将标记”描述的是待实现期望。
6. 无依据断言的人工决定仍沿用现有证据流程；不成立/未决定不能直接确认。编辑移除或补资料后按现有流程重新检查，不自动清空风险。
7. 列表摘要为“单个商品 · 名称”“多个商品 · A + B（N）”“活动 · 名称”；结果页附说明与福利摘要；旧任务保留旧单品显示。
8. 创建和生成保持现有两个独立按钮语义；选项不完整、加载中或提交中禁用；错误保留输入，展示服务端 request_id。

## 与契约或约束不一致的地方

- 当前 `POST /tasks` 只接收一个 product_id，不能用假商品或把多品 id 塞入 brief 绕过；对象联合字段、活动必填校验、商品关联及生成输入需 A 单独设计契约。
- 对象快照、版本/任务响应、旧数据兼容与证据归属尚无约定；多品资料需区分事实属于哪个商品，不能把 A 商品卖点套给 B。
- 新活动依据预提示的判断接口/逻辑未实现；缺资料时是否允许创建沿用现有创建语义，不能声称已经拦截所有优惠断言。
- 图中“已确认文案”等新导航是本轮设计上下文，尚未实现前不能加到生产导航。没有修改任何前后端、公共组件或 token。
